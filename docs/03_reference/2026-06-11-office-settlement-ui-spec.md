## 0. 설계 원칙 — 이 두 화면이 무엇인가

> **정산 화면 = 회사 서류다. 정산서가 스토리텔링이다.**
> **사무실 화면 = 직장이다. 다음 출동 전 잠깐 숨 고르는 곳이다.**

### 0.1 픽션 문법 (전 요소에 관통)

플레이어는 사후처리부 외근직이다. 모든 UI 텍스트는 이 픽션을 벗어나지 않는다.

| 게임 개념 | UI에서 쓰는 이름 |
|---|---|
| 런 종료 결과 | **작업 정산서** |
| strain 수집량 | **메모리 회수량** |
| 사망 | **현장 인원 미회수** |
| 타이머 만료(sweep) | **광역 정밀소독 — 강제 회수** (서류는 통제불능을 인정하지 않는다) |
| 사망 시 strain 상실 | **시말서** (자동 작성본) |
| 탈출 성공 | **정상 철수 완료** |
| meta 강화 구매 | **장비 요청서 제출** |
| 계약 선택 | **업무 배정 수락** |
| 정밀 계약 | **정밀처리 계약** |
| 대량 계약 | **대량정화 계약** |
| 다시 출동 | **출동 준비 완료** |

### 0.2 톤 기준

- **차갑고 행정적인 껍데기 + 내부에서 새어나오는 인간적 온기**. 팀장과 엘의 코멘트가 빈틈을 채운다.
- 폰트: 기존 HUD의 `Pretendard-Regular` 계열. 타이틀급은 굵게, 수치는 모노스페이스 감각.
- 색 팔레트: HUD 문법 계승 — 기본 오프화이트(#E8E8E0), 강조 시안(#00D4C8, 탈출 지점 색), 경고 앰버(#F5A623), 위험 레드(#E53E3E). 배경은 어두운 그레이(#1A1A1F) 기반.

```

           ── 타이머 만료(Swept) ────────────────┤
                                                  ▼
                                        ┌─────────────────┐

                                        │  (timeScale=0)   │

                                        └────────┬────────┘
                                                  │
                                        [계속] 버튼 또는
                                        자동 3초 후
                                                  ▼
                                        ┌─────────────────┐
                                        │   사무실 화면    │
                                        │  (timeScale=0)   │
                                        │  허브 패널       │
                                        └────────┬────────┘
                                                  │
                              ┌───────────────────┼──────────────────┐
                              ▼                   ▼                  ▼
                        [장비 요청]          [계약 선택]         [엘 대화]
                     (MetaUpgrades)      (계약 보드 확장)     (현재 코스메틱)
                              │                   │
                              └──────────┬────────┘
                                         ▼
                                 [출동 준비 완료]
                                  RunManager.StartMission()
                                         ▼
                                     [인게임]
```

### 흐름 설계 결정

- **씬 전환 없음**: 헌장 §부록A 결정 계승. 인게임 씬 위에 풀스크린 UI 패널을 띄운다(timeScale = 0). 로딩 없이 정산 → 사무실 전환.
- **정산 → 사무실 전환**: "계속" 버튼 또는 자동 3초 후. 버튼을 누르지 않아도 정산 읽을 시간을 준다.
- **사무실에서 인게임 진입은 단일 버튼**: "출동 준비 완료"만. 계약을 바꾸지 않으면 직전 계약 유지.

### 2.2 정보 위계 (시선 순서)

| 순서 | 요소 | 이유 |
|---|---|---|
| 1st | **결과 스탬프** (정상 철수 / 미회수 / 강제 회수) | 살았나 죽었나가 가장 먼저 온다. 크고 색으로 구분. |
| 2nd | **메모리 회수 확정량** | 이게 메타 성장으로 연결되는 수치. 가장 크게. |
| 3rd | **처리 건수 + 소요 시간** | 성취감 수치. 카운트업으로 도파민 납품. |
| 4th | **팀장/엘 비고** | 픽션 온기. 빠르게 읽혀야 함 — 2줄 이내. |
| 5th | **누적 통산** | 성장감. 작은 폰트로 충분. |

### 2.3 결과 스탬프 디자인

세 가지 결과를 **도장 모양 텍스트 이미지**로 표현. GUI Pro의 Badge/Tag 계열 프레임 위에 올린다.

| 결과 | 텍스트 | 색 | 각도 |
|---|---|---|---|
| 탈출 성공 | **정상 철수 완료** | 시안(#00D4C8) | 약간 기울기 없음, 정자 |
| 사망 | **현장 인원 미회수** | 레드(#E53E3E) | -3° 기울기 |
| 타이머 만료 | **광역소독 — 강제 회수** | 앰버(#F5A623) | 0° |

> Solo Dev Cost: **S** (단순 텍스트+색+약간 기울기. GUI Pro Badge 프레임 적용 가능)

### 2.4 서사 내장 텍스트 실례 (한국어, 15개+)

아래는 실제 화면에 쓸 수 있는 텍스트 초안이다. 카피를 최종 확정하기 전 수정 가능하나, **어법은 이 방향 유지** — 행정 서류 + 인간 온기의 혼합.

#### 정산서 헤더 고정 텍스트

```
사후처리부 / 로컬지점 제N구역
작업 정산서 (사본 2부)
작업일: [날짜] / 담당자: 현장직 (사번 미표기) / 작업코드: OP-[런 인덱스 4자리]
```

#### 스탬프 및 상태 레이블

```
① 정상 철수 완료
② 현장 인원 미회수  
③ 광역 정밀소독 시행 — 강제 회수 처리
```

#### 처리 실적 항목명

```
④ 이상개체 처리 건수:
⑤ 메모리 회수량 (총):
⑥ 메모리 확정 (운반 성공분):
⑦ 회수 소실 (미철수 또는 강제회수):
⑧ 작전 소요시간:
```

> **설계 의도**: "회수 소실"이라는 라벨이 사망/패배를 단어 하나로 전달한다. "당신이 죽어서 잃었다"가 아니라 "메모리가 소실되었다"로 서술 — 감정적 거리와 묘한 냉소가 공존한다.

#### 팀장 비고란 코멘트 (조건별, 랜덤 풀에서 출력)

```
[탈출 성공 / 처리 건수 높을 때]
⑨ "수치 좋다. 본사 눈치 안 봐도 될 것 같은데."

[탈출 성공 / 처리 건수 낮을 때]
⑩ "어쨌든 돌아왔으면 된 거야. 다음엔 더."

[사망]
⑪ "현장 인원 미회수 처리. 장비는 재신청해. 본사에 보고는 내가 막을게."

[타이머 만료]
⑫ "광역소독 같은 소리 하네. 폭격이야 그거. 다음엔 더 일찍 빠져나와."

[메모리 회수량 최저 (0~5)]
⑬ "회수량 낮다. 뭐 하다 온 거야."
```

> **설계 의도 (이중 레지스터 — 렉시콘 §5.2)**: 서류는 "광역 정밀소독"이라 쓰고, 팀장은 "폭격이야 그거"라고 말한다. 같은 사실의 2회 전달(명료성) + 공문의 차가움과 입말의 온기 충돌이 이 화면의 픽션 엔진이다. 팀장 코멘트를 추가할 때는 항상 서류 어휘를 입말로 번역·반박하는 방향으로 쓴다.

#### 엘(L-17) 코멘트 (스탬프 아래, 1줄)

```
[탈출 성공]
⑭ "귀환 확인. 다음 출동 대기 중입니다."

[사망]
⑮ "연산 오류 아닙니다. 사용자 재확인에 시간이 걸렸습니다."

[타이머 만료]
⑯ "광역소독 개시 확인. 저도 나왔습니다."

[처리 건수 50+ 탈출 성공]
⑰ "처리 건수 비정상입니다. 긍정적 의미입니다."
```

> **설계 의도**: 엘의 코멘트는 항상 어딘가 박자가 어긋난다. "연산 오류가 아닙니다"는 걱정을 부정으로 표현하는 엘의 말투다. 세계관 바이블 §5-3 반영.

### 2.5 연출 순서 (카운트업 도파민 설계)

정산 화면 진입 시 수치를 한 번에 표시하지 않는다. 아래 순서로 등장한다.

```
0.0s — 화면 페이드인 (0.3s)
0.3s — 헤더(서류 제목) 등장
0.5s — 결과 스탬프 "도장 찍기" 등장 (스케일 1.2 → 1.0, 0.15s)
        + 사운드: 도장 찍는 소리 (간결, 무겁게)
0.8s — "이상개체 처리 건수" 레이블 등장
0.8s~1.8s — 처리 건수 카운트업 (실제 값까지, 속도는 값에 비례)
1.9s — "메모리 회수량" 레이블 등장
1.9s~2.9s — 메모리 총량 카운트업
2.9s — "확정 회수량" 레이블 등장
        + 탈출 성공 시: 총량과 동일 (시안색 표시)
        + 사망/강제회수 시: 0 (레드 표시, 잠깐 0.2s 떨림 연출)
3.1s — "소요 시간" 등장 (카운트업 없이 직접 표시)
3.3s — 팀장 비고란 등장 (타이핑 효과, 0.5s)
3.8s — 누적 통산 등장
4.0s — "계속" 버튼 활성화
```

> **Solo Dev Cost: M** — DOTween으로 카운트업(`DOCounter`)과 스케일 팝(`DOScale`) 구현 가능. 도장 사운드만 별도 SFX 파일 필요.

### 2.6 "회수 소실" 연출 (사망/강제회수 전용)

사망이나 강제회수 시, 확정 회수량이 0이 될 때 별도 연출이 붙는다.

```
메모리 회수량: [총량 카운트업] → XXX 단위
                              ↓ 0.3s 후
회수 소실:       [빨간 텍스트로 등장] ─ XXX 단위 소실
                              ↓
확정 회수량:      0 단위
```

> 화면에서 숫자가 올라갔다가 "소실"이라는 단어와 함께 확정량이 0이 되는 시퀀스. 번 카드처럼 긴장감이 있다. Rogue Legacy의 유산 파괴 연출과 같은 심리 원리.

### 2.7 시말서 (사망 전용 — 렉시콘 §5.1 신규 장치)

사망 정산서 하단(누적 통산 위)에 접힌 서류 1블록이 추가로 등장한다:

```
┌──────────────────────────────────────────────────────────────┐
│  시말서 (자동 작성본)                                          │
│  ──────────────────────────────────────────────               │
│  본인은 부주의로 인해 회사 자산(메모리 XXX 단위)을          │
│  현장에 유실하였기에 경위를 보고하며, 재발 방지를 약속합니다.  │
│                                                                │
│  서명: ____________ (자동 처리됨)                              │
└──────────────────────────────────────────────────────────────┘
```

- **strain 상실의 픽션 설명체**다 — "당신이 죽어서 잃었다"를 회사는 "자산 유실 경위서"로 처리한다.
- 백미는 서명란: **본인의 사과문이 자동 작성되고 자동 서명된다.** 죽은 직원의 반성문을 시스템이 대필하는 것 — 제2조(본사 무변론)의 정산 화면 버전.
- 연출: 팀장 비고 0.3s 후 슬라이드 인. 텍스트 1블록 + 정적 표시면 충분.
- Solo Dev Cost: **S** (static text, 사망 분기에서만 활성)

### 3.2 계약 보드 설계 (장르 다이얼의 시각화)

계약 선택이 "그날의 느낌"을 바꾼다. UI에서 두 계약의 성격 차이가 읽혀야 한다.

#### 카드 레이아웃 (각 계약)

```
┌────────────────────────────────────────────────┐
│  [계약 유형 태그]  정밀처리 계약               │
│                                                │
│  작업 내용: 지정 이상개체 집중 처리            │
│  예상 조우: 소수 정예 / 엘리트 출현 높음       │
│  메모리 기대치: 건당 고품질                 │
│  제한 시간: 15분 (단일 목표 완료 시 조기 철수 가능)│
│                                                │
│  [엘 한 줄 평] "추적 정밀도 지원 가능합니다." │
└────────────────────────────────────────────────┘

┌────────────────────────────────────────────────┐
│  [계약 유형 태그]  대량정화 계약               │
│                                                │
│  작업 내용: 구역 내 이상개체 전량 처리         │
│  예상 조우: 다수 / 연속 웨이브                 │
│  메모리 기대치: 물량으로 확보               │
│  제한 시간: 30분 (구역 목표 달성 시 철수)      │
│                                                │
│  [엘 한 줄 평] "과부하 가능성 있습니다."      │
└────────────────────────────────────────────────┘
```

> **Phase 1 주의**: 헌장 §2에 따르면 계약 유형은 Phase 2 §3번 시스템이다. Phase 1 스켈레톤에서는 **계약 보드 UI를 표시하되, 두 카드 중 하나를 "준비 중" 상태로 표시**해 자리만 잡아둔다. 실제 분기 로직은 Phase 2에서. 자세한 컷라인은 §5 참조.

#### 선택 시각 피드백

- 선택된 카드: 시안 테두리 + 배경 약간 밝게
- 선택 안 된 카드: 어둡게 dimmed (opacity 0.5)
- Phase 2 잠금 항목: 레이블에 `[준비 중]` 태그 + 전체 opacity 0.3

### 3.3 메모리 현황 패널

Phase 1은 생체 계열 1종만. Phase 2 자리 4개를 잠긴 상태로 표시해 성장 예고.

```
메모리 현황
─────────────────────────────────
[생체]  ████████░░░░░░░  XXXX 단위
[강골]  ── 미분류 (데이터 부족)
[신경]  ── 미분류 (데이터 부족)
[제어]  ── 미분류 (데이터 부족)
[과열]  ── 미분류 (데이터 부족)
```

> "미분류 (데이터 부족)"이라는 표현은 픽션 내 설명이다. 게임 외적으로 "아직 개발 안 됨"이 아니라, 세계관 내에서 "해당 계열 메모리를 아직 수집하지 않아 분류 기준이 없음"으로 읽힌다.

### 3.4 장비 요청서 패널 (MetaUpgrades)

Phase 1은 강화 항목 2개(데미지 배율 / 연사 배율).

```
장비 요청서
─────────────────────────────────
지급 요청 항목           비용
─────────────────────────────────
강화 탄약 (데미지 +X%)   XXX 단위  [요청]
경량 기어 (연사 +X%)     XXX 단위  [요청]
─────────────────────────────────
(이하 항목 준비 중)
(이하 항목 준비 중)
─────────────────────────────────
```

- **[요청] 버튼**: 메모리 충분 시 활성(흰색), 부족 시 비활성(dimmed)
- 이미 구매한 항목: `[적용 중]` 텍스트로 교체 (재구매 방지, Phase 1 스켈레톤은 단순 1회 구매)
- "준비 중" 행: opacity 0.3, 클릭 불가

### 3.5 엘(L-17) 아바타 표시

사무실 우상단 고정. Phase 1은 텍스트 아이콘 수준.

```
┌───────────────────────────────┐
│  L-17                        │
│  ◎  [상태 아이콘 1개]         │
│  "[엘 한 줄 텍스트]"          │
└───────────────────────────────┘
```

엘 텍스트는 상황별 랜덤 풀:

```
[기본 대기]
"출동 대기 중입니다. 언제든지."

[직전 런 사망했을 때]
"재확인 완료. 다음 출동 준비 됐습니다."

[메모리 충분할 때]
"요청서 처리 가능 상태입니다."

[메모리 거의 없을 때]
"회수량이 낮습니다. 참고 정보입니다."

[첫 번째 런 시작 전]
"현장지원 프로토콜 시작합니다."
```

## 5. Phase 1 최소 구현 컷라인 vs Phase 2 확장 슬롯

### 5.1 Phase 1 최소 구현 (지금 만들 것)

| **팀장 비고 텍스트** | 필수 | 조건별 string pool, 5개 이상 |

| **출동 준비 완료 버튼** | 필수 | `RunManager.StartMission()` |

### 5.2 Phase 2 확장 슬롯 (자리만 비워둘 것)

| 슬롯 | Phase 2 시스템 | Phase 1에서 처리 방법 |
|---|---|---|
| **계약 선택 실제 분기** | 헌장 §4 #3 (계약 2유형) | 카드 UI 있되 선택 로직 없음. 항상 기본값 |

### 5.3 Phase 2 진입 조건 (정산/사무실 관련)

헌장 게이트 4문항 §3 중 이 화면과 직접 연결된 것:

> 게이트 3: **"정산 화면에서 '다음 런엔 강해져서 온다' 기대가 생기는가?"**

이 게이트를 통과하지 않으면 Phase 2 사무실 기능(계약 분기, 계열 분화)을 구현하지 않는다.
확정량 카운트업 + 장비 요청 → 다음 런 기대가 생기는지가 검증 포인트다.

## 6. 구현 핸드오프 메모 (Gameplay 에이전트용)

이 섹션은 Gameplay 에이전트가 구현 착수 전에 읽는다.

### 6.1 데이터 소스

| UI 표시값 | 소스 | 헌장 §부록A 계약 |
|---|---|---|
| 처리 건수 | `RunStats.Kills` | RunManager → SettlementReport |
| 메모리 총량 | `RunHarvest.Total` | SettlementReport에 포함 |
| 확정 회수량 | `StrainWallet.LastDeposit` | Deposit 호출 시 저장 |
| 소요 시간 | `RunStats.ElapsedTime` | SettlementReport에 포함 |
| 결과 분류 | `RunOutcome` enum | Extracted/Died/Swept |
| 보유 메모리 (사무실) | `StrainWallet.Balance` | 실시간 |
| 강화 구매 가능 여부 | `StrainWallet.TrySpend` | MetaUpgrades를 통해 |

### 6.2 씬 구조

- **씬 전환 없음.** Greybox_ScanLit 씬 위에서 GameObject `SettlementPanel`과 `OfficePanel`이 각각 활성/비활성으로 전환된다.
- 두 패널 모두 `timeScale = 0`에서 동작해야 한다 → `Time.unscaledDeltaTime` 사용. DOTween은 `SetUpdate(true)`(unscaled) 적용 필수.
- 실행 순서: 런 종료 → `RunManager.OnRunSettled` 이벤트 → SettlementPanel 활성 → 사용자가 "계속" → OfficePanel 활성 → "출동" → OfficePanel 비활성 → `StartMission()`.

### 6.3 텍스트 시스템

- 팀장 비고/엘 코멘트는 `ScriptableObject` 배열로 저장 권장. 조건(Outcome + 수치 범위)을 key로 풀에서 랜덤 선택.
- Phase 1은 하드코딩 string array도 충분. Phase 2 서사 확장 시 SO로 마이그레이션.

### 6.4 HUD 문서 §1 함정 계승

진행 바 사용 시 `white_square.png` (8×8, Single, border 0) + `Image.Type.Filled`. `RectMask2D`로 클리핑. 9-slice로 늘이면 알약 변형 발생.
