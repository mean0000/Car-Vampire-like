## 1. 이번에 확정된 것

### 1.1 무기 베이스 = 4클래스, 런당 1택
- **카타나 / 대검 / 권총 / 드론** 4종이 베이스.
- **런 시작 시 1종 선택 = 그 런은 그 클래스로 끝.** 동시 보유(로드아웃) ❌, 해금·교체 ❌.
- 모델 = **하데스 무기 픽 + 20MTD 캐릭터**. 어느 무기를 메인하나(클래스 간)가 리플레이 축.
- ⚠️ pivot 스펙이 "총기 중심"으로만 적혀 있던 갭을 메우는 결정 — 이제 스펙 테이블에 명시됨.

### 1.2 깊이 2층 (헌법 방향 — 조문 문구는 미확정)
| 층 | 어디서 | 깊이 출처 | 레퍼 |
|---|---|---|---|
| **층A 런 안** | 한 클래스 키우기 | **입력 타이밍 × 빌드**. 카드는 수치(+%)가 아니라 "언제 누르나"를 바꿔야 깊이 | **20MTD 트리** |
| **층B 런 사이** | 4클래스 중 뭘 메인 | 클래스마다 다른 손맛·빌드 = 다양성 | **하데스 무기/양상(Aspect)** + 20MTD 캐릭터 |

### 1.3 카타나 첫 볼트 카드 (그대로 유효)
- 카타나 = 4클래스 중 하나를 통째로 완성하는 **수직 슬라이스** (멀티무기 화면의 조각 아님).
- **간소 5종:** ①발도연마(→충전/릴리즈 카드로 교체 합의) ②환류가속=**킬 환류(처형 템포)** ④연격가속 ⑤격노임계 ⑥발놀림(중립 안정판).
- **3택** (현 LevelUpChoiceUI 그대로). 풀이 5종이라 4택은 80% 노출 → 선택 죽음. 3택이 더 날카로운 검증.
- **출현 가중 쏠림 ×1.6** (하드월 ❌).
- **입력 보상 레버 = ④** (콤보 타이밍 성공 시 증폭) — 차별점 검증 핵심.
- 보류(후속): ③일섬(동사변형) · G3[연쇄 인가].

## 2. 레퍼 보정 이력 (왜 이렇게 됐나)

1. 시작: "엠버 앤 블레이드 카드 = 하데스 Boon 직접 원본" (내 1차 분석)
2. Codex + GameDesign 이중 검증 → **부분기각**: 계열 락인은 하데스에 없음(하데스=다신 혼합), 엠버 ≈ 하데스 ∪ DMD. 1순위 = **20MTD 트리**, 하데스는 레어도+듀오 2조각만(이미 박힘).
3. 깊이 분석: "단일무기는 무기 조합 깊이 못 씀, 깊이=입력타이밍×빌드"
4. **유저 정정**: 무기는 4종(카타나/대검/권총/드론)이다 → 3의 "게임 전체 단일" 전제 **틀림**.
5. 분기 질의 → **"런당 1종(클래스)"** 확정 → 런 안은 단일무기라 3의 깊이 축은 유효, 조합 깊이는 **런 사이**에 부활. 2층 그림으로 봉합.

연동 메모리: `card_reference_map_20mtd`, `weapon_classes_per_run_depth`, `katana_core_loop_bolt`.

## 3. 미결 (다음 세션 판정)

- **드론 동작** — 자동공격형 vs 조준/입력형 미정. 자동이라도 자기 클래스에 갇혀 카타나/근접의 "누를 때만" 철학은 안 깸. 드론 클래스 설계 시 결정.
- **깊이 헌법 D-0~D-4 조문** — 방향은 동결, 정확한 5개 조문 문구는 GameDesign에서 다시 받아 확정 필요. (⚠️ 대용량 인라인 출력 금지 — §5 참조)
- **대검/권총 클래스** — 카타나 외 3클래스는 미설계.

## 5. 운영 메모 — API 서로게이트 에러

이 세션은 `400 ... no low surrogate in string` 에러로 한 번 막혔음.
- **원인:** 대용량 Codex/에이전트 출력 + 비BMP 이모지가 글자수 한도에서 절단 → 외짝 서로게이트 → JSON 직렬화 실패.
- **확인:** 디스크 텍스트 파일 379개 스캔 결과 외짝 서로게이트 0 → 오염은 파일이 아니라 라이브 컨텍스트(절단)였음. 재오염 우려 없음.
- **예방:** ①대용량 출력은 파일로 저장 후 `Read limit`으로 부분만 ②큰 출력에 비BMP 이모지 쓰지 말 것(BMP 기호만).
