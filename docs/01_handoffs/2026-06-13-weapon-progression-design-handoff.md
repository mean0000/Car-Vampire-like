# 핸드오프: 2026-06-13 — 무기 체계 + 성장 구조 설계 (GameDesign / `gd` 착수 브리프)

> **목적**: 새 세션에서 **`gd`(GameDesign 에이전트)** 로 "무기를 뭘 쓰고 / 어떻게 강해지는가" 구조를 정확히 설계한다. 이 문서가 착수 브리프 — gd는 맨땅이 아니라 여기서 출발한다.
> **에이전트**: `.claude/agents/gamedesign.md` (모델 opus, 제안→유저 판정, **동결 권한 없음**, ★레퍼런스 추적 의무 + 기존 권위 재정합 의무).
> **새 세션 호출**: 이 문서를 주고 `gd`로 띄운다. (에이전트 레지스트리가 세션 시작 시 고정돼서, 만든 당일 세션에선 호출이 안 될 수 있음 → 새 세션 필수.)

## 1. 임무

주인공이 **칼 · 몽둥이 · 주먹 · 총을 다 쓰는** 풀 아스널을 전제로:
- **(A) 무기 체계** — 무엇을 들고, 무기끼리 어떻게 갈리며(역할/대가), 어떻게 발현되나.
- **(B) 성장 구조** — 런 안에서 강해지는 축(in-run) vs 런 간 영구 성장(meta), 줍는 것의 흐름, 카드/시너지.

★**맨땅 설계 금지.** 레퍼런스 추적(§4) + 기존 권위 재정합(§3)을 경유한 제안만 유효.

## 4. 레퍼런스 추적 과제 (웹 조사 → 우리 뼈대 역산)

- **Shape of Dreams** — 전투 느낌·런 구조·성장 곡선·스킬/빌드 발현. (우리 전투 본진 레퍼)
- **Hades II** — 방 단위 빌드크래프트(선택 누적·시너지·보상 구조). → 우리 런 내 성장 구조 모델.
- **Brotato / Backpack Battles / Duckov** — 인-런 무기 강화·인벤토리·추출 경제. → "줍는 것=설계도/부품" 흐름 모델.
- 각 제안에 "이 구조는 레퍼 X의 Y를 추적했다" 명시. 근거 없는 발명 금지.

## 6. 병렬 상태 (간섭 주의)

- **애니메이션 = Animation 에이전트/다른 세션 전담** — gd는 건드리지 않는다. 단 **무기 로스터는 애니 가용성과 정합**해야 한다:
  - 베이스 전투 애니 후보 = RPG Char Mecanim Pack / Protofactor ANIMSET(우리 몹 벤더·in-place).
  - 화려 시그니처 = Grruzam 스타일리시 에코시스템(쌍권총·칼) 또는 Raisecreation 애니.
  - **화려함 위치**: 권총/쌍권총/근접 칼 = *모션으로* 화려 / 라이플·샷건 = *VFX·카메라·처치연출로* 화려. 상세 = [[project_combat_anim_sourcing]].
- 무기에 "쌍권총(아키mbo)" 또는 "카타나" 같은 시그니처를 넣을지 = 화려 애니 에코시스템 선택과 연동된 **유저 판정 대기** 항목.

## 7. 판정 대기 (유저 — gd가 제안에 물음표로 올릴 것)

- 화려 애니 에코시스템 픽: **Grruzam(프리미엄·묵직) vs Raisecreation(애니·저가)** — 무기 발현 톤과 직결.
- 무기 로스터 확정 범위(아키mbo·카타나 시그니처 추가 여부).
- 런 내 vs 런 간 성장 비중(어디서 더 강해지는 맛을 줄지).

## 8. 출력 규율

산출물 없으면 의견이다. 제안 문서를 `docs/03_reference/`에 작성(작성일·상태·판정 질문·레퍼 추적 근거·변경 이력 표). 동결되면 권위 문서 갱신 + 구현 스펙을 Gameplay에 넘길 형태로. 네이밍은 직접 정하지 말고 Story(렉시콘) 경유. 구현은 Gameplay. 동결은 유저.
