## 1. ★ 도로 배치 핵심 규칙 (반드시 지킬 것)

오늘 "도로가 건물과 따로 논다"의 원인 2개를 잡았다. 새 도로를 깔 때 이 규칙을 어기면 다시 어긋난다.

### (A) 피벗이 +X/−Z 코너에 있다 (center 아님)
Generic 도로/보도 전 조각의 피벗은 타일 **+X/−Z 모서리**, 메시는 −X/+Z로 채워진다. 건물(밑면-중앙 피벗)과 같은 좌표에 놓으면 반 타일 어긋난다.

**배치 공식 (회전·크기 무관, 검증됨):** 타일을 격자중심 `(cx,cz)`에 정확히 놓으려면 —
```
1) 일단 position=(cx,cz)로 둔다
2) 렌더러 바운드 중심(worldCenter)을 측정
3) position += (cx - worldCenter.x, 0, cz - worldCenter.z)
```
회전을 바꾸면 메시중심이 또 이동하므로 **회전 적용 후 위 보정을 다시** 한다.

### (B) Road_01은 흐름과 평행한 두 변에 연석이 있는 단순 직선
- `yaw=0` → 동서(X) 흐름, 남북(N/S) 변에 연석
- `yaw=90` → 남북(Z) 흐름, 동서(E/W) 변에 연석
- **세로 leg는 yaw=90, 가로 run은 yaw=0**으로 깔아야 연석이 주행방향을 가로지르지 않는다. (오늘 전부 yaw=0이라 세로 leg에 연석이 사다리처럼 생긴 게 문제였음)
- 키트에 **10m 폭 전용 90° 코너 조각은 없음**(Intersection_02는 5×5). 직선끼리 L-코너는 얇은 연석선 seam이 불가피 → 그레이박스 허용. 정 깔끔하게 하려면 코너 셀에 연석없는 `Road_Small_01`(curb-less) 4장 패치 실험 여지.

## 4. 도구 / 작업 방법 메모

- **Unity MCP `Unity_RunCommand`**: 클래스명 반드시 `CommandScript : IRunCommand`, `internal`. 변경 시 `result.RegisterObjectModification(go)` 먼저, 생성은 `RegisterObjectCreation`, 삭제는 `result.DestroyObject`. `result.Log`는 `{0}`에 **오브젝트 참조만** 치환(float 포맷 `{0:0.0}`는 리터럴로 찍힘 → C# 보간문자열 `$"{x:0.0}"` 쓸 것).
- **탑다운 PNG 렌더**(URP에서 동작 확인): 임시 직교 카메라(`rotation Euler(90,0,0)`, `clearFlags SolidColor`, `cullingMask ~0`) + 임시 Directional Light → `cam.targetTexture=rt; cam.Render(); ReadPixels; EncodeToPNG`. 코어 구역은 center(10,200,110)/orthoSize 85가 적당. 렌더 후 임시 오브젝트 즉시 DestroyImmediate.
- **검증 루프**: 배치 → 탑다운 렌더 → Read 툴로 PNG 확인 → 수정. 멀티앵글(`CaptureMultiAngleSceneView`)은 비싸므로 입체 확인이 꼭 필요할 때만.
- 진단 스크립트(도로-도로/건물-도로 겹침 산출)는 렌더러 바운드 AABB 교차로 계산. 단, **세로로 큰 메시(크레인 지브 등)는 공중 부분이 바운드에 잡혀 오탐** → 면적/관통 임계로 거르거나 눈으로 확인.
