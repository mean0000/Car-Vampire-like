★ 코너(Road_3E 등) — 차도 중심선 ✕, "bbox 모서리 맞대기" ○ (유저 검증):
곡선의 차도(검정)는 bbox 중앙이 아니라 바깥쪽 모서리에 붙어 있음. 중심 정렬하면 어긋나고 연석 단차가 생김. 곡선 bbox의 바깥 모서리를 이웃 직선의 모서리에 일치시키면 차도+연석이 동시에 맞물림.
검증 예 (rot0 S→E 곡선 + 12폭 직선 Road_1A, 직선 bbox x[664,676]/z[-6,6]): 3E.bbox.minZ ≈ 직선.maxZ(6)(세로 맞댐) + 3E.bbox.maxX == 직선.maxX(676)(바깥=오른쪽 모서리). → pivot(664, 19.9).
pivot 공식(3E 기준): pivot_x = 이웃_바깥모서리X − 12, pivot_z = 이웃_윗변Z + 14. 회전 시 "바깥 모서리"도 회전.

3. 두 시스템 비혼용 — 룩 충돌(흙 군사 ↔ 깨끗 도시). 구역 경계(초크포인트)에서 전환.
4. 자투리·공터·전환부 = Generic 자연 지면(Dirt/Ground) 활용.

★ 도로-그래프 빌드 알고리즘 (Claude + Codex gpt-5.4 검증)

핵심 원칙: "타일 먼저"가 아니라 "그래프 먼저". 빌더 계약 = 그래프 역할 → 통행성(traversability) → 키트 실현 (위에서 아래로). 타일 모양에서 그래프를 추론하지 말 것 — Generic은 코너가 없어 "그래프는 맞는데 도로 조립 불가" 실패가 생김.

is_critical_path 계약

  • 막는 오브젝트 배치 금지 · 양방향 통행 항상 보장 · 게이트 외 협착 금지.
  • 게이트 = is_critical_path=true + initially_blocked=true (돌파 전까지 의도적 차단).

구역별 그래프 불변식

  • 지배 흐름방향 1개 + 보조 연결 1~2개 — 없으면 1km가 "분리된 아레나"로 느껴짐.
  • 존 스케일 루프 1개 + 게이트 주변 국소 우회로 (단순 ≥1루프는 약함 — 나무형 복도로 전락).
  • 막다른길 비율 A 40% / B 25% / C 15% — 단 분기 말단에만 적용(교차점 제외, 지표 왜곡 방지).
  • 일방통행 금지 — 막혔다고 느낌. 안쪽 당김은 보상 밀도로(드롭율↑).

빌드 5단계 순서 (그래프 우선, 파괴는 외형)

1. 구역 외곽 + 진출입 앵커를 A→B→C 순서로, 모든 게이트를 지나는 척추 경로 1개 확정.
2. 구역별 그래프 생성 — 위 불변식 적용. 게이트 후보는 척추 엣지에만.
3. 게이트 edge-cut 검증 — 게이트 막힌 엣지 제거 시 그 너머가 연결 끊겨야(우회로 있으면 게이트 무의미) + 그 존 다른 곳에 우회 루프 존재.
4. 파괴/노이즈·rupture 레이어를 얹되 연결성 계약 유지하며 국소 조정(파괴는 외형/맥락이지 통행 권위 아님).
5. 그래프를 키트 타일로 실현 → 배치 후 연결성 재검증(Generic 기하가 추상 그래프를 깰 수 있어 B/C 특히).
⚠ 가장 큰 맹점(Codex): 파괴를 먼저 깔면 "도시"가 아니라 "미로 긁기"처럼 보임 → 그래프(연결성 보장)를 먼저, 파괴는 나중·재검증.
