# 카메라 시스템 명세 (Camera Bible)

> **작성일**: 2026-06-10 · **상태**: v1.0 확정 (앵글 실측 스터디 + Gameplay/art/lv 교차 검토 + 구현·검증 완료)
> **이 문서가 권위인 범위**: 프레이밍 · 추종 동역학 · 리드 · 충격 언어 · 상태 레이어 · 포스트 결합 가드레일.
> **구현체**: `PlayerCameraRig.cs` (단일 권위 — 카메라를 만지는 다른 코드 금지, API 경유만)

## 0. 원칙

1. **카메라는 시스템이다** — 각도·무빙·충격·포스트가 한 몸. 부분 수정 금지, 이 문서 기준으로만.
2. **회전·높이(Y)·피치 런타임 변경 절대 금지** — 탑다운 멀미 + 스크린스페이스 틸트시프트 밴드 보존. 모든 동적 반응은 XZ 평면 오프셋과 FOV(±3° 이내)로만.
3. **카메라 시간은 실시간(unscaled)** — 슬로모(산데비스탄 등) 중에도 카메라 반응은 1배속.

## 1. 프레이밍 (정적 — 씬 트랜스폼이 보존)

| 항목 | 값 | 근거 |
|---|---|---|
| 피치 | **45°** (구 58°) | 결투 프레이밍 앵글 스터디(58/52/45/38 실측 렌더) — 인물 실루엣·대치선 가독의 변곡점. 부수효과: 수평 차폐(모퉁이 문법) 강화 |
| 거리 | **15m** (구 20m) | 위 스터디 페어링 |
| FOV | 50 | 유지 |
| 줌 | **금지** | 3자(Gameplay/art/lv) 일치 — 공간 인식·정찰성 파괴. 킬의 존재감은 이펙트의 공간 점유(킬 링)로 |

## 2. 추종 동역학

| 노브 | 값 | 비고 |
|---|---|---|
| followSmoothTime | **0.18s** (구 1.0 — 흐물거림의 주범이었음) | 액션 기준 0.1~0.25 밴드. XZ만, Y는 즉시 |
| 커서 리드 (이원) | **평시 fraction 0.18 / max 2m · 주시(우클릭 홀드) ×2.2 / max 5.5m** (구 0.4/4 상시) | 2026-06-11 이원화 — 평시=연결감만(차분), 주시=의도 기반 시프트(코너 너머 보기). `SetAimState`가 우클릭으로 구동(보조사격은 Q 임시 이양). B-009 정조준 의식의 입력 기반 |
| 속도 리드 | 0 (꺼짐) | 골목 질주 미리보기 필요 시 0.15s/2m부터 시험 |

## 3. 충격 언어 — 3채널 (전부 XZ, 합산 캡 0.5m)

| 채널 | 형태 | 트리거 | 값 |
|---|---|---|---|
| **Kick** | 방향성 — 반동 반대로 밀렸다 지수 복귀 | 발사(`PlayerCombat`) — **예약제(2026-06-11): 무거운 단발(산탄 or 발사간격≥0.3s)만.** 연사류는 카메라 충격 0(히트스탑·머즐·사운드가 담당 — Hades/DOOM 모델, RoR2 Commando 반면교사) | 0.1m / decay 20 (≈70ms). 샷건 ×1.8. **묵직함의 주력. 충격 유무=무기 계열의 촉각 언어** |
| **Kick 연사 서스테인** | 어택-서스테인 — 첫 발만 풀 킥, 연사 중엔 고정 밀림 유지(임펄스 반복 없음), 사격 중지 시 지수 복귀 | 킥 간격 < 0.25s(히스테리시스 ×1.2) | 밀림 0.05m / 램프 0.08s. **근거: 연사 킥 반복=5~15Hz 진동(전정계 민감 대역)→멀미. 진동을 0Hz 밀림으로 치환. "모든 발이 무거우면 무게는 소멸" — 무게는 첫 발에만** |
| **Shake** | 무방향 Perlin | 발사 보조 0.06(샷건 ×2) · 피격 0.4 | damping 12 / freq 22. **연사 서스테인 중 발사 보조 쉐이크는 생략**(22Hz 펄린이 멀미 공범) |
| **Punch-In** | 방향성 — 처치 방향으로 당겨졌다 복귀 | 킬(`ZombieController`, 원거리·근접 공용) | 0.18m / decay 14. **킬 피드백 클램프(0.15s/1회)와 게이트 공유** — 호드 대량킬 발작 방지 |

## 4. 상태 레이어 (API 준비 완료 — 구동은 후속 시스템)

- `SetAimState(bool)` — 조준 의식(숨 고르기-정조준) 진입 시: 커서 리드 ×1.35 + FOV −2.5° 를 6/s 속도로 블렌드. **조준 입력 시스템이 생기면 연결** (현재 미구동).
- 울트(산데비스탄) 상태 — 카메라는 추가 동작 없음(연출은 4층 Volume·잔상 소관). 시간은 이미 unscaled라 충돌 없음.

## 5. 포스트 결합 가드레일

- **★평시 틸트시프트 폐지 (2026-06-11 v1.3, 유저 콜 "평소 틸트시프트 포기해도 좋아")**: 평시 화면은 블러·탈색·어둠 0의 완전 클린. 밴드·콘 스택 전체가 **조준(우클릭) 게이트** — AimBlend로만 들어온다. 그 대가로 **FOV ±3° 제약 해제**(제약의 근거가 평시 밴드의 월드 정합이었음) → **조준 줌 −8° = 진짜 줌**. 콘 스택은 플레이어 추적형(매 프레임 WorldToViewportPoint)이라 FOV 변화에 안전. **카메라 높이·피치 금지는 그대로 유지.**
- **시야 콘 틸트시프트** (2026-06-11, `TiltShiftConeDriver`): 캐릭터→조준 방향 부채꼴은 Y 밴드가 열리고(선명), 콘 밖은 블러 바닥 0.6 + 채도 −30%. 가드레일: ①`coneBlend` 0=현행 밴드와 완전 동일(회귀 노브) ②콘 방향 각속도 200°/s 제한(블러 경계가 화면을 쓸면 그 자체로 멀미) ③근접 반경 0.1(uv.y) 무조건 선명(밀착 위협 보호) ④블러 최대치 `_MaxBlurRadius` 불변 — 정보 삭제 수준 금지. 호드 측후방 가독성은 플레이로 계속 감시(pm 우려 항목 — "측후방에서 맞아 죽은" 빈도 늘면 blend 하향/조준 시 한정 검토).
- FOV 동적 변화는 ±3° 이내(틸트시프트 월드 투영 오차 ~1% 한계).
- Cinemachine 비도입 — 현 리그 확장으로 충분(검토: Gameplay 2026-06-10). 컷신 수요 발생 시 재평가.
