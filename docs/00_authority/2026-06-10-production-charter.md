## 0. 선언 — 탐색 단계 종료

지금까지는 탐색·테스트 단계였다: 그래픽 베이스라인 v1(4층 룩데브 구조) 잠금, 총기 타격감 패스, 좀비 리그/애니 파이프라인 확립, 디자인 대전환 문서화. **충분했다.** 이제부터는 생산 모드 — 하나씩 꼼꼼하게 만들어 잠그고, 돌아보지 않는다.

단, "돌아보지 않는다"의 적용 대상을 정확히 가른다:

| 돌아보지 않는 것 (완벽하게 만들고 잠금) | 돌아보는 것 (반복이 본질) |
|---|---|
| 시스템 아키텍처 · 인터페이스 계약 | 수치 (드롭률·타이머·강화비용 — 전부 SO) |
| 플레이테스트 게이트를 통과한 시스템의 역할 | 게임감 튜닝 · 페이싱 곡선 |
| 그래픽 treatment (베이스라인 v1, 이미 잠김) | 콘텐츠 양 (계약·이벤트·변형 추가) |

## 1. "돌아보지 않아도 되는" 3보장

1. **플레이테스트 게이트** — 시스템마다 완료 선언 전에 게이트 질문을 먼저 정의하고, "예"가 나와야 잠근다. 완성도 → 검증이 아니라 **최소 동작 → 검증 → 완성도** 순서.
2. **인터페이스 동결** — 시스템은 내부 구현이 아니라 다른 시스템과 맞닿는 계약만 고정 (StrainInventory API, 디렉터 입력값, 타이머 이벤트, 런 상태 머신). 내부는 갈아도 이웃이 안 깨진다.
3. **수치의 거처 분리** — 모든 밸런스 수치는 ScriptableObject. 로직(불변)과 수치(가변)를 섞지 않는다. "돌아보기"가 값 조정으로 끝나게.

## 2. Phase 1 — 루프 스켈레톤 (최우선, 거칠게·그러나 골조답게)

가장 비싼 미해결 질문 = "이 루프가 재미있는가". 빌드 2개가 재미없었고(진단: 당김+무게 부재), 신규 디자인은 처방이지 검증된 답이 아니다. 개별 시스템을 100% 완성도로 만들기 전에 **루프 전체가 한 바퀴 돌아야 한다.**

| # | 시스템 | 스코프 (이만큼만) |
|---|---|---|
| 1 | 작전 타이머 | HUD 카운트다운 + 0이면 sweep 연출(화면 플래시 수준) + 런 종료. 업무 연장·escalation 분기 없음 |
| 2 | strain 드롭 | 좀비 사망 시 자동수집 재화 **1종(생체만)**. 계열·등급 분화 없음 |
| 3 | 탈출 = cash-out | 탈출 지점 + 헬기 호출 딜레이 15~20초 → 성공 시 strain 확정, **사망 시 전량 소실** |
| 4 | 사무실 = 메뉴 한 장 | 런 사이 화면: 보유 strain + 무기 강화 1~2개 구매 + 재출격. 텍스트 UI |
| 5 | 정산 화면 | 텍스트: 수확 N / 생존 여부 / 누적 |
| 6 | escalation 최소형 | 시간 경과 → 스폰량 증가 곡선 하나. 기존 스포너 그대로 |

**스켈레톤에 안 들어가는 것**: 싱크 게이지, 5계열 로스터, 스폰 디렉터, 이벤트, 보험, 계약 유형, 좀비 캐스팅, 모든 아트·그래픽 작업.

**거칠어도 버리는 코드는 아니게**: 스켈레톤부터 3보장(§1) 적용 — 이 골조가 본 건물의 골조가 된다.

## 3. 게이트 — 4문항 (Phase 2 진입 조건)

플레이테스트에서 전부 "예"가 나오면 생산 모드 본격 진입. 하나라도 "아니오"면 스켈레톤 단계에서 수정(여기서는 싸다).

| # | 질문 | 검증 대상 |
|---|---|---|
| 0 | 메타 없이도 **좀비를 가는 것 자체가 10분간 즐거운가**? | 축1 처치력 — 이게 아니오면 어떤 루프도 못 구함 |
| 1 | 타이머가 실제로 **마음을 급하게** 만드는가? | 무게 엔진 ① |
| 2 | **"보스/다음 업무까지 가느냐 vs 비상 탈출로 확정하느냐"** 고민이 생기는가? (2026-06-10 개정 — 중간 탈출 제거에 맞춤) | 무게 엔진 ② (press-your-luck) |
| 3 | 정산 화면에서 **"다음 런엔 강해져서 온다"** 기대가 생기는가? | 당김 엔진 |

## 4. Phase 2 — 시스템별 생산 (하나씩 잠금)

> **★2026-06-10 개정**: 루프 스켈레톤 가동 후 판명 — 게이트 0번("좀비를 가는 것 자체가 즐거운가")의 **토대(카메라·인식·스폰 근본·킬 아크)가 부재**해 게이트 평가 자체가 불가능했다. 따라서 **0번 품목 = 전투 질감 파운데이션**이 디렉터보다 먼저다. 게이트 4문항 평가는 전투 질감 랩 통과 후 수행.

각 항목: **스펙 동결 → 구현 → Stab+Codex 병렬 리뷰 → 플레이테스트 게이트 → 잠금.** 잠근 것은 다시 열지 않는다 (수치 제외).

| 순서 | 시스템 | 완료 정의(게이트 질문) |
|---|---|---|
| **0** | **★전투 질감 파운데이션 — 게이트 0 최소셋** (`2026-06-10-combat-texture-foundation.md` §8) — ①피격 사다리+히트스탑+3계층 탄 판정 ②인식 미니멀 3상태(Dormant/Alert/Chase)+그르렁 ③런지+grapple. 잔여(카메라·조준·소리 사다리·잔여 상태)는 게이트 0 통과 후, 스폰 5규칙·배치 인구는 1번(디렉터)과 통합 (검토 반영 v1.1 — 7단계 전부를 0번에 넣으면 Phase 2 절반을 삼킴) | 전투 질감 랩에서 좀비 1마리 교전이 다섯 비트(발견 주도권/결정/조준 무게/킬 아크/청구서)를 통과하는가? |
| 1 | **스폰 디렉터** (파운데이션 §4 스폰 원칙 위에 — 구식 스포너 폐기) | Build→Peak→Relax 톱니가 체감되는가? 스폰 출처가 단일한가? 티어 곡선 파라미터 내장 |
| 2 | **3계열 로스터** (생체/신경/제어 — 오늘 확립한 리그 인프라 위에) | 세 계열이 서로 다른 결정을 강제하는가? 호드 속에서 제어가 즉시 식별되는가? |
| 3 | **계약 2유형 = 장르 다이얼** (정밀/대량, §4.6) | 계약 선택이 그날의 "느낌"을 실제로 바꾸는가? 1번 미션 호드 피날레가 갈증을 만드는가? |
| 4 | **싱크 게이지 + 능력** | 90~99 폭주 밴드를 "타고 싶은가"(칼날 라이딩)? 처벌감이 아니라 도박감인가? |
| 5 | **산재 보험 + 사무실 허브 승격** (§4.7) | 죽음이 덜 억울하면서 여전히 무서운가? 정산서가 웃긴가? |
| 6 | **strain 계열·등급 분화 + 크래프팅 v1 + 드롭 세리머니** | "3성 과열 필요 → 계약 수주" 타게팅이 실제로 작동하는가? |
| 7 | **이벤트 MVP 4종** (감염 군집 이동/보급 투하/소독 드론 오인사격/격리 봉인) | 런마다 다른 이야기가 생기는가? |
| 8 | **좀비 캐스팅 + 나노봇 시그니처** (도시 시민 변형, 회백 피부, 계열별 발광 패턴) | 화면이 "관료제가 만든 조용한 재난"을 말하는가? Hell Express 옆에 놓고 안 부끄러운가? |
| 9 | **시가지 맵 + 그래픽 큐 5번** (빛기둥·바닥 브레이크업·고임 안개) | 베이스라인 새 씬 체크리스트 통과 + 여러 무드 조건에서 버티는가? |

> 순서 근거: 1~3이 전투의 분당 리듬(디렉터)과 다이얼(계약)을 만들고, 4~6이 3축과 경제를 완성하고, 7이 런의 이야기를, 8~9가 비주얼 생산. **아트(8~9)는 시스템 잠금 후** — 캐스팅·시그니처 설계는 로스터(2)와 다이얼(3)이 잠겨야 대상이 확정되기 때문.

## 5. 운영 규칙

- **그래픽 작업 동결**: 베이스라인 v1 유지보수 외 신규 그래픽 패스 금지. 큐 5번은 Phase 2 순서 9에서.
- **작은 편집 예외**: 잠긴 시스템의 수치 조정·버그 수정은 헌장 절차 없이 (CLAUDE.md 소편집 규칙).
- **헌장 개정**: 게이트 결과가 디자인 전제를 깨면 — 그때는 돌아본다. 그게 게이트의 존재 이유다. 개정은 이 문서 변경 이력에 기록.

## 부록 A — 스켈레톤 시스템 계약 (2026-06-10 동결)

> 동결 대상 = 아래 API·이벤트·SO 구조. 내부 구현·수치는 자유.

**RunManager** (씬 싱글톤): `RunPhase { Office, InMission, Extracting, Settled }` / `RunOutcome { Extracted, Died, Swept }` · `Phase` · `OnPhaseChanged` · `OnRunSettled(SettlementReport)` · `StartMission()` `RequestExtraction()` `CancelExtraction()`. 런 생명주기의 단일 권위 — Settle 경로 3개(타이머 만료=Swept / `PlayerController.OnPlayerDied`(기존)=Died / 탈출 완료=Extracted)는 전부 RunManager로 수렴.

**OperationTimer**: `Remaining` · `OnTick(float)` · `OnExpired` · `Begin(seconds)`. (Phase 2 자리: `Extend()` — 업무+시간 재심 통과 시에만)

**RunHarvest(런 내, 휘발)** ↔ **StrainWallet(영구, 저장)** 분리: Harvest = `Add(StrainDef, n)` · `OnHarvested` (← 드롭 세리머니 자리). Wallet = `Balance` · `TrySpend` · **`Deposit(harvest, retentionRate)`** — 탈출 1.0 / 사망 0.0 / ★Phase 2 보험 = 0.3, 보험 전체가 이 인자 하나로 진입.

**MetaUpgrades**: `TryPurchase(UpgradeDef)` · `GetDamageMultiplier()` `GetFireRateMultiplier()` — PlayerCombat은 배율 훅 한 줄로만 통합.

**ExtractionPoint**: 트리거 존 진입 = 호출 시작, 반경 이탈 = 취소, `OnExtractionComplete`. 비주얼 = 시안 이미시브 마커 (라이팅 바이블 색상 예산: 시안 = 추출 지점, ×2 HDR).

**Persistence**: `ISaveStore { Load(); Save(json); }` — 스켈레톤 구현 = persistentDataPath JSON. 저장 대상 Wallet+Upgrades뿐.

**SO 4종**: `RunConfig`(미션 시간·헬기 딜레이·탈출 반경) / `StrainDef`(계열·등급 — 스켈레톤은 Bio 1개, Phase 2 = 에셋 추가만) / `UpgradeDef`(비용·효과 — 데미지·연사 2개) / `EscalationProfile`(경과시간→스폰율 커브 — ★디렉터 seam: Phase 2 디렉터가 이걸 입력으로 스포너 교체. 디렉터 인터페이스 자체는 미동결).

**구조 결정**: 씬 전환 없음(사무실/정산 = 풀스크린 UI 패널 + timeScale 0) · UI는 이벤트 구독만(로직 0) · 레거시 비접촉(Car\*, XP/카드=불꽃놀이 유지, 옛 CraftingSystem/SyncRateManager 비접촉) · 기존 코드 침습 = ZombieController 사망 `RunHarvest.Add` 1줄 + PlayerCombat 배율 훅 1줄 + ZombieSpawner에 EscalationProfile 주입.

**폴더**: `Scripts/Run/` `Scripts/Meta/` `Scripts/Data/`.
