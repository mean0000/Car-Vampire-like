## 0. 재미 본진 선언 (유저 확정, 2026-06-10)

> **쫄깃하게 좀비 한 마리 한 마리를 잘 잡으면서 성장하고, 그 성장의 도파민으로 더 많은 좀비·엘리트·보스를 처치하고, 일을 끝낸 뒤 탈출한다.**

- 탈출은 재미가 아니라 **런의 마무리**다. 중간 탈출 없음. 비상 탈출 = 긴급 베일아웃 전용.
- "좀비 쏘고 탈출하기"는 우리 게임이 아니다. **한 마리의 쫄깃함 × 성장 도파민**이 본진이고, 메타 루프(strain·크래프팅)는 그 위에 선다.
- 방법론: 닌텐도가 교토를 걸으며 밀도를 체득했듯이 — **원칙의 차용이 아니라 디테일의 체득**. 레퍼런스는 감상이 아니라 측정한다 (몇 발, 몇 초, 몇 프레임).

## 1. 한 마리 교전의 다섯 비트

쫄깃함은 단일 속성이 아니라 5개 비트의 연쇄다. 각 비트가 설계돼 있어야 한 마리가 "사건"이 된다.

| 비트 | 내용 | 핵심 질문 | 상태 |
|---|---|---|---|
| 1 발견 | 누가 먼저 보는가 | 발견의 주도권이 의미 있는가 | §2 확정 |
| 2 평가·결정 | 쏠까, 어디서, 지금? | 이 한 발의 청구서는 얼마인가 | §3 확정 |
| 3 조준 | 정지의 대가 | 조준이라는 행위에 무게가 있는가 | ⬜ 리서치 대기 |
| 4 한 발 한 발 | 킬의 아크 | 매 발이 킬을 시각적으로 전진시키는가 | ⬜ 리서치 대기 |
| 5 마무리·후과 | 보상과 청구서 회수 | 결정(비트2)이 결과로 돌아오는가 | §3.3 확정 |

## 2. 비트 1 — 좀비 인식 모델 (확정)

현행 "반경 안 = 즉시 추격"을 폐기하고 아래로 대체한다. **1순위 레버 3종: 틱당 확률 누적 + Alert 텔레그래프 + 그르렁 전파.**

### 2.1 인식 상태기계

```
Dormant ←→ Wander → Investigate → Alert → Chase ⇄ Attack → SearchLKP → (Wander 복귀)
```

> ⚠ **7상태다** (검토 정정): 기존 Attack 상태(공격 쿨다운·PerformAttack 귀속처)는 **유지**한다 — 제거가 아니라 Alert·SearchLKP·Dormant/Wander가 추가되는 것. **마이그레이션 체크리스트**: ① `IsAggro`(ScanPulseController가 읽음) = Chase∥Attack 정의 갱신 ② 시그널 좀비 `SignalCoroutine`은 Chase 진입 경로가 늘어나도(Alert→/피격→/재발견→) `_hasSignaled`로 1회 보장 ③ 스폰 애니메이션(`_spawning`) 중 상태 = Dormant로 정의 ④ strain 드롭(`HarvestStrain`)·MMF 사망 연출은 Die 경로 그대로.

| 상태 | 행동 | 진입 | 이탈 |
|---|---|---|---|
| **Dormant** | 정지/엎드림 (배치 인구 기본) | 맵 배치 시 | 소리(발소리급 초과) 또는 시야 판정 성공 |
| **Wander** | 그룹 앵커 주변 저속 배회 | Dormant 해제, Search 만료 | 소리/시야 이벤트 |
| **Investigate** | 소리 지점으로 *걸어감*, 도착 후 5~8초 배회 | 소리 들림(시야 미확정), 동료 그르렁 | 시야 확정→Chase / 타임아웃→Wander |
| **Alert** | **멈춰서 응시 1~2초** + 느린 접근 (텔레그래프 — "쟤가 날 봤나?") | 시야 확률 판정 일부 누적 | 게이지 충전→Chase / 이탈→Investigate |
| **Chase** | 전력 추격. **진입 순간 그르렁 방출 (사운드 이벤트, 반경 6~10m)** | 시야 확정 또는 피격 | 시야 상실→SearchLKP |
| **SearchLKP** | 마지막 목격 지점으로 이동, 10~20초 배회 | Chase에서 시야 상실 | 재발견→Chase / 만료→Wander |

### 2.2 파라미터 원칙 (수치는 전부 SO — 시작값)

- **시야 = 원뿔 ~120° + 틱당 확률 누적** (PZ식. 이진 판정 금지 — Alert 단계가 확률 누적에서 자연 발생). 거리 **상한 = 화면 반경 이하** (Zero Sievert "화면 밖 공격 = 싸구려 죽음" 반면교사). 빛·플레이어 행동(이동/사격)이 노출 확률 스케일.
- **청각 = radius(전파 거리) × volume(유인력) 분리** (PZ식). 벽 감쇠 최소 1단계.
- **개체 분산 ±30%**: 시야·청각을 개체별 랜덤화 — 같은 무리에도 눈 밝은 놈/장님이 섞여 "안전거리를 확신할 수 없음"이 쫄깃함을 만든다 (PZ Random 옵션의 정수).
- **전파는 그르렁 경유만**: Chase 진입 시 그르렁(작은 반경 사운드)을 방출하고, 듣는 좀비는 Chase가 아닌 **Investigate**로만 승급. 무선 브로드캐스트식 그룹 어그로 링크 금지. → **"한 마리씩 떼어내기"의 수학적 보장.** 예외는 제어 계열(디스럽터)뿐 — 로스터 설계대로.
- **동시 활성 Chase 상한** (시작값 25~30): 초과분은 Investigate까지만. 성능+가독성 보호.
- **성능 원칙 (검토 반영)**: 인식 판정(시야 레이캐스트·청각)은 **N프레임 분산(스태거드 업데이트)** + 거리 LOD(멀수록 판정 주기 길게). 전 인구가 매 FixedUpdate에 레이캐스트하는 현행 구조 금지 — 수백 개체 전제.
- **★호드와의 화해 (검토 반영 — 모드별 프로파일 불필요)**: 그르렁 규칙은 **배치 인구에만** 적용된다(떼어내기 보장). 디렉터가 보내는 Mob/Peak 웨이브는 **스폰 시점부터 어그로 상태로 도착**한다(L4D mob 방식) — 호드 압박은 인식 규칙이 아니라 디렉터의 소관. 인식 시스템은 하나, 대량 정화 계약의 분쇄감은 디렉터가 웨이브 규모로 만든다.

## 3. 비트 2·5 — 소리 사다리와 청구서 (확정)

### 3.1 소리 사다리

플레이어의 모든 행동에 소리 반경을 부여한다. **소리 크기의 선택 = 교전 규모의 선택** — 이게 "이 한 발의 결정"의 실체다.

| 행동 | 반경(시작값) | 비고 |
|---|---|---|
| 걷기 | ~3m | |
| 달리기 | ~6m | |
| 근접 처치 | ~5m | 조용한 처리 옵션 (스텔스 아님 — 교전 규모 통제) |
| 권총 | ~25m | PZ 75타일의 우리 스케일 번역 |
| 샷건/폭발(추후) | ~50m | 사다리 최상단 |

### 3.2 철칙

- **소리는 절대 스폰을 트리거하지 않는다. 존재하는 좀비를 끌어올 뿐.** (State of Decay "소리=스폰" 반면교사 — 커뮤니티가 즉시 알아채고 최악의 메커니즘으로 평가)
- 소리는 디렉터의 intensity *입력값*은 될 수 있다 (직접 스폰 권한은 없음 — 기존 디렉터 설계와 정합).
- **★옛 "소음 이중처벌 소멸" 결정과의 화해 (2026-06-10 유저 판정 — 소리 사다리 채택)**: 옛 결정이 죽인 것은 "소음 → 소환/스폰"(즉발·비가시·통제 불가)이고, 그건 위 철칙으로 계승된다. 소리 사다리의 "소음 → 기존 좀비 Investigate"(점진·가시·통제 가능)는 다른 메커니즘이며, 재미 본진(한 발의 결정)의 필수 장치로 **코어 채택**. 제어 좀비 트리거(탐지/존재)는 변경 없음 — 근거만 "디스럽터는 존재 자체가 위협"으로 갱신 (코어 디자인 §4.5 참조).

### 3.3 비트 5 — 청구서 회수

- 킬 직후: strain 코어 드롭 세리머니 (기존 확정: 엘 한 줄 분석).
- 총성 수 초 후: 사다리 반경 안의 좀비들이 Investigate로 일어나 **그 방향으로 걸어오기 시작** — 한 발의 결정이 풍경의 변화로 회수된다. 이 "일어나서 걸어오는 풍경"이 비상 탈출 판단의 정보가 된다.

## 4. 스폰 원칙 (확정)

### 4.1 기본 인구 = 배치형 (Zero Sievert/PZ식)

- 미션 로드 시 POI 밀도 기반으로 **Dormant 좀비를 미리 깔아둔다** (디렉터가 budget 배분). 플레이어가 처음 보는 좀비의 90%는 "이미 거기 살던" 것이어야 한다.
- L4D wanderers처럼 진행 전방+옆길에도 배치 — 정찰과 "어느 길로 갈까"가 의미를 가진다 (익스트랙션의 당김).

### 4.2 동적 스폰 = Mob/Peak 전용, 5규칙 동시 적용 (L4D식)

1. 카메라 프러스텀 + 마진(2~3m) 밖
2. **최소 거리 = 카메라 실측 가시 경계 + 마진으로 유도** (⚠ 검토 반영: L4D의 12m를 그대로 쓰면 우리 탑다운 카메라에선 화면 끝 바로 밖 팝인이 된다 — 구현 시 프러스텀 지면 교선을 실측해 그 바깥으로) / 최대 ~30m
3. NavMesh로 플레이어까지 **도달 가능한** 위치만 (⚠ 모듈 이음매 NavMesh 단절 — 기존 함정 메모리)
4. 최근 스폰 사용 영역 쿨다운 (같은 모서리 반복 방지)
5. **가시 경계 근처에 스폰해야 할 때는 출현 포인트(창문·맨홀·차 밑·덤불) 경유 필수** (검토 반영: "가능하면"→필수 승격) — "스폰"이 아니라 "숨어 있었다"로 읽힘

### 4.3 환수

- 디스폰 = 화면 밖 + 30m 초과 + 비교전 상태에서만. 인구는 디렉터 budget으로 환수 (L4D AAS 방식).
- 보너스 트릭: 새 개체 생성 대신 **멀리 있던 배치 좀비를 디렉터가 이동시켜 도착**시키면 영수증이 완벽하다.

## 5. 레벨 디자인 기본 원칙 (CEDEC 2017 젤다 BotW — 원리만 차용, 디테일은 우리 것으로 체득)

1. **인력(引力)**: 플레이어를 끌어당기는 매력물(크기·보상·불빛)을 목표 동선 *사이에* 의도 배치 — 자유롭게 가는 줄 알면서 디자이너의 동선을 탄다. 우리 인력 후보: 불빛(어둠 속 라이트 — 라이팅 바이블의 Ember 풀이 곧 인력 장치), strain 밀집 무리, 보급 투하, 이벤트, 미확인 POI.
2. **사각(死角) — 삼각형 법칙**: 시야를 가르는 지형은 ①분기(정복/우회) ②정점의 기대감 ③너머의 것을 *서서히* 드러냄. 대형=랜드마크 / 중형=인력을 감추는 사각 / 소형=엄폐물·역동성. **현행 그레이박스는 평탄+개방이라 "서서히 드러남" 0 = 긴장 0.**
   - **★탑다운 사각 성립 조건 (검토 반영 — 빠져 있던 전제)**: 피치 58° 부감에서 높이 h인 차폐물이 가리는 지면 깊이 ≈ h×0.62. 3m 건물 = 1.9m만 가림, 우리 좀비는 키 ~4m라 **수직 차폐로 좀비를 숨기는 건 사실상 불가능** (6m+ 건물 필요). → **우리의 사각 주력 장치는 수평 차폐(90° L-코너·골목·통로 꺾임)다.** 삼각형 법칙은 평면 동선(코너를 돌면 서서히 드러남)으로 번역해 적용. 건물 내부는 오클루전 마스킹(지붕 가림) 도입 시에만 사각이 됨 — 그 전엔 실내 배치에 의존 금지.
3. **현실 투영 — 밀도의 체득**: 배치 밀도는 수식이 아니라 걸어보며 체득 (닌텐도는 교토를 걸었다). 우리 시작 감각: 도시 블록 하나당 교전 1~2회 + 인력 1개. 그레이박스에서 반복 보정.

> 인식 모델(§2)과 레벨(§5)은 한 몸이다 — 사각이 있어야 "발견의 주도권"이 생기고, 배치 인구(§4.1)가 있어야 정찰이 의미를 가진다.

## 6. 비트 3·4 — 카메라·조준·킬의 아크 (확정 — Hades/ZS/PZ/Vlambeer/사쿠라이 리서치 기반)

### 6.1 쫄깃함의 공통 원리 7 (교차 분석 결과 — 설계 헌법)

1. **시간을 만진다, 양은 중요도에 비례** — 일반 히트는 아주 짧게, 킬/크리티컬만 길게. 맞는 쪽만 흔들어라(사쿠라이).
2. **이진 히트/미스 폐기** — 모든 발사가 세계에 흔적을 남겨야 "한 발이 의미 있다" (PZ B42, ZS glancing).
3. **조준 판정은 발사 전에 보여준다** — 쏘기 전에 결과를 예측·책임질 수 있어야 명중이 내 실력이 된다 (ZS "확률 아니라 정확도 기반" 선언).
4. **피격 리액션은 사다리, 면역은 티어** — flinch→stagger→넉백→넉다운 단계 + 엘리트는 아머로 사다리 면역 (Hades). 스턴락 방지가 곧 위협 보존.
5. **카메라는 조준 의도를 따라간다** — 커서 오프셋(HM) + 사격 반대 방향 카메라 킥(Vlambeer). 쉐이크는 절제+토글.
6. **한 발 실패의 실제 비용** — 단, 좌절 관리 장치와 반드시 쌍으로 (HM 즉시 리스타트, PZ 월드 지속).
7. **텔레그래프 문법의 일관성** — 윈드업 실루엣은 공격마다 고유, 경고색은 한 문법 (Hades II 크로노스 반면교사).

### 6.2 비트 4 — 킬의 아크 (수치는 SO, 시작값)

- **히트스탑**: 일반 히트 30~50ms / 킬샷 80~120ms / 엘리트 아머 파괴 ~150ms. **전역 timeScale 금지 — 피격자 Animator만 정지+흔들기** (사쿠라이: 히트박스는 안 움직임, 공격자·카메라는 계속 흐름). 호드 게임에서 전역 슬로모는 연사 시 피로.
  - **★통합 경로 (검토 반영 — 블로커였음)**: 기존 `ZombieController.Die()`의 전역 `MMTimeScaleEvent`(timeScale 0.03/0.05s)는 신규 히트스탑 구현 시 **제거·대체**한다. 공존 금지. 기존 주스 패스(머즐·넉백·MMF 피드백)는 유지하고 히트스탑만 교체.
  - **★킬 피드백 스택 클램프 (검토 반영)**: 카메라 킥·쉐이크·킬 사운드는 **시간창(예: 0.15s)당 1회로 클램프, 초과분은 병합** — 대량 정화 계약에서 초당 5~10킬 시 카메라 발작·오디오 폭주 방지.
- **3계층 탄 판정**: 풀히트 / 스침(50% 데미지 + flinch만) / 그레이즈(미스여도 소량 데미지 + 비틀 확률). 탑다운 20m에서 픽셀 에임은 불가하므로 "맞췄나"(디지털)가 아니라 **"얼마나 잘 맞췄나"(아날로그)**.
  - **기하학 정의 (검토 반영 — 미정의였음)**: 탄도 세그먼트와 좀비 캡슐 축의 최단 수평거리 d 기준 — **d ≤ 0.4m 풀히트 / 0.4 < d ≤ 0.7 스침 / 0.7 < d ≤ 1.0 그레이즈** (수치는 SO, 기존 스피어캐스트 r0.4 파이프라인의 반경 분기 확장으로 구현 — 재작성 아님).
- **피격 사다리**: flinch(0.1~0.2s 상체 경직 — 모든 히트 보장, **한 발 = 적 행동 1회 거부**) → stagger(0.3~0.5s 정지) → knockdown(넘어짐 + 기상 1~2s, 다운 중 추가타 보너스) → 사망. **연속 히트 시 경직 내성 증가**(스턴락 방지). 넉백은 `KnockbackPower ≥ Resistance` 문턱 + Force 2변수 (HoT 모델).
- **엘리트 티어**: 아머 게이지 동안 사다리 면역(시각: 전용 게이지) → 게이지 파괴 순간 큰 스턴 보상 (Hades 직수입). 잡몹과 엘리트의 "질감"을 피격 리액션 유무로 분리.

### 6.3 비트 3 — 조준 모델

- **정확도 원뿔 + 수렴**: 이동 시 원뿔 확장, 정지+조준 유지 0.5~1s에 수렴(ZS aim settle), 발사 반동으로 재확장. **"정지의 대가" 트레이드오프의 구현체.**
- **사전 고지**: 기존 조준 레이저의 색 변조 — 흰색 = 풀히트 보장 거리 / 적색 = 스침 위험 (ZS 크로스헤어 문법). 확률 롤을 숨기지 않는다.
- **탄약·재장전**: 마지막 2~3발 사운드 차별화, 잔량은 디제시스(총기·사운드) 우선. 재장전 중 이동 감속은 **10~15%만** (Death Must Die 과감속 반발 교훈 — 커밋 긴장은 만들되 조작감은 살림).

### 6.4 카메라

- **커서 오프셋**: 지면 평면에서 `플레이어→조준점` 벡터의 **25~35% 지점**을 팔로우 타깃으로 (HM은 ~50%이나 그건 풀탑다운+원힛 기준 — 피치 58° 원근에선 낮게 시작, 부드러운 damp 필수). 조준 방향의 정보를 먼저 보여주는 것 = 비트 1(발견)의 카메라적 지원.
- **카메라 킥**: 사격 시 반동 반대 방향 0.1~0.2 유닛 밀었다 복귀 (Vlambeer).
- **쉐이크**: 카메라 거리(20m)에 비례해 양 보정 (사쿠라이 ⑧ — 멀수록 화면상 변위가 작아 보임), 옵션 토글 제공. 전투 상시 줌인은 비채택 — 익스트랙션에서 주변 정보 = 생존 정보. 줌은 향후 정조준 모드의 "정보 트레이드"로만 (ZS 스코프 문법).

### 6.5 한 마리의 위협 (비트 4의 반대편 — 좀비의 공격)

- **런지 윈드업 0.4~0.6s**: 상체 젖힘 + 전용 사운드 큐. 계열별 윈드업 실루엣 고유(원리 7).
- **grapple**: 잡히면 수 초 스턴 + 탈출 입력 — 무한 카이팅 치즈를 깨는 안티치즈 (PZ 펜스 런지 문법).
- **근접 피격의 시스템 비용 (2026-06-10 유저 판정 — 검토 반영)**: ~~싱크 게이지 비용~~ → **HP만으로** 확정. 싱크에 피격 비용을 실으면 코어가 2회 금지한 "싱크=처벌" 위반 + 능력 사용 위축으로 싱크 시스템 자체가 죽는다 (pm 검토 치명 판정). 대신 **근접 피격을 아프게(HP의 15~20%/대)** — 사망 = 수확 소실이 이미 경제와 연결돼 있어 "한 대도 맞기 싫다"는 HP로 성립한다. 랩 테스트에서 부족하면 별도 물림 트랙을 재논의.

## 7. 방법론 — 전투 질감 랩 (Combat Feel Lab)

룩데브 랩과 동일한 규율로:

1. **랩 씬**: 복도 하나 + 좀비 1마리부터. 그다음 3마리 무리, 그다음 코너(사각) 하나. 호드·레벨·메타는 그 뒤.
2. **레퍼런스 측정**: 감상 금지 — Zero Sievert에서 좀비 1킬에 몇 발·몇 초, Hades 히트스탑 몇 프레임, PZ 발견→교전 호흡 몇 초. 수치로 기록해 우리 시작값으로.
3. **통과 기준**: 좀비 1마리 교전이 다섯 비트를 모두 통과할 것 — 발견에 주도권이 있고, 쏘기 전에 생각하고, 조준에 무게가 있고, 매 발이 보이고, 청구서가 돌아온다.
4. 랩 통과 후에야 헌장 게이트 0번을 평가한다.

## 8. 구현 순서 (검토 반영 개정 — "0번 한 칸"이 Phase 2 절반을 삼키지 않게 게이트 0 최소셋으로 축소)

| 2 | **인식 미니멀 3상태** — Dormant → Alert(응시 텔레그래프) → Chase + 그르렁 전파 (Wander/Investigate/SearchLKP는 후속) | "발견의 드라마"의 최소 골격 |
