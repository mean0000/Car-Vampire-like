## 그래픽 기준점: Hell Express

**본 프로젝트 그래픽의 기준점은 Hell Express (Full Metal Bagel, Unity)다.** 동일 장르(아이소메트릭 익스트랙션 슈터)의 라이팅·포스트프로세싱·분위기 설계를 기준으로 삼는다. 모든 비주얼 판단이 갈릴 때 "Hell Express라면 어떻게 했나"를 먼저 확인한다.

스크린샷 분석(2026-06-10)에서 추출한 **Hell Express 라이팅 5원칙** — 이 문서 전체의 철학적 기반:

1. **한 장면 = 한 지배 색상.** 고채도 보색은 게임플레이/내러티브 의미가 있는 곳에만
2. **안개가 라이팅의 절반.** 배경 밸류 압축 + 깊이 레이어링 + 빛 기둥의 캔버스
3. **캐릭터 가독성 = 색온도 대비.** 쿨 환경 + 웜 플레이어 풀 (휘도 대비는 무너져도 색상 대비는 살아남는다)
4. **빛 풀은 넓고 소프트.** 광원 점이 아니라 빛이 닿은 면적을 보여준다
5. **미드톤 보존.** 암부에도 정보를 남기고, 하이라이트를 태우지 않는다

차용 범위 주의: **색·안개·풀·틸트시프트의 "문법"만 가져온다.** Hell Express의 고밀도 PBR 머티리얼 스타일은 비차용 — 본 프로젝트는 로우폴리 통일이며, 면이 단순할수록 위 5원칙의 색·밸류 설계가 오히려 더 잘 드러난다.

### 노출 원칙 3개

1. **밝기 재분배**: 명부를 올리려면 키라이트, 암부를 올리려면 앰비언트. postExposure로 미는 것 금지 (명부만 타고 암부는 그대로).
2. **암부에도 정보**: 화면 최암부 바닥값 ~RGB 25–35. 정보 없는 검정 영역 금지.
3. **하이라이트 안 태움**: 최고 휘도는 이미시브/블룸 코어에만 허용. 라이트 풀이 흰색으로 클리핑되면 강도 초과.

### 색상 예산표

| 색 | 역할 | 비고 |
|---|---|---|
| 웜 오렌지 (1.0, 0.6±, 0.35±) | 플레이어 / 안전 / 키라이트 | FollowLight·골든 풀 |
| 레드 | 위협 (좀비·위험구역) | 좀비 액센트로 예약, 환경 남용 금지 |
| 시안 (0.35, 0.75, 0.85) | 보상 / 상호작용 / 추출 지점 | 라이트 금지, **이미시브 마커만** (×2 HDR) |
| 청보라 | 앰비언트 그늘 | 황혼 프로파일의 zenith 계열 |

**ACES 채도 규칙**: 액센트 색은 HDR ×2 이하 유지. ×6 이상이면 톤매퍼가 흰색으로 밀어버림 (시안 마커 실험으로 확인). 눈에 띄게 하려면 휘도가 아니라 채도·배치로.

## 2층 — 황혼 프로파일 (`Atmosphere_Dusk_v2.asset`)

### "Frozen Golden Hour" 기법

시간(태양 고도)은 **15:00에 고정**하고, AtmosphereProfile의 색 속성을 전부 `constant` 모드로 황혼색 동결. 이유: 물리적 일몰 고도(5°)는 밀폐 아레나 바닥에 직사광이 못 닿음 → 고도는 거짓말하고 색으로 시간을 말한다 (영화 매직아워 보정과 동일 논리).

| 속성 | 값 |
|---|---|
| sunlightColor | (1.0, 0.62, 0.38) × **1.7** — ⚠ COZY sunlightColor는 색에 HDR 강도가 실림. 1.0 캡 상수로 바꾸면 1스톱 어두워짐 |
| ambientLightZenithColor | **(0.35, 0.40, 0.75)** — 2026-06-10 확정. 그늘 바닥의 쿨 카운터포인트 (웜 골든 풀과의 대비 축) |
| ambientLightHorizonColor | (0.80, 0.48, 0.34) |
| ambientLightMultiplier | 2.0 |
| skyZenith / skyHorizon | (0.28, 0.26, 0.50) / (0.95, 0.55, 0.35) |
| fogColor 1→5 | 웜 로즈 (0.50, 0.38, 0.42) → 딥 퍼플 (0.18, 0.16, 0.34), **알파 = 0.03 / 0.10 / 0.25 / 0.45 / 0.75** |
| fogStart 1→4 | **18 / 30 / 45 / 70m** — 플레이필드(카메라-바닥 ~20m) 안쪽은 포그 면제 |
| fogDensityMultiplier | 0.6 |

> ⚠ **COZY 포그 규칙 (2026-06-10 사고 기록)**: COZY fogColor의 **알파 채널이 해당 단계의 포그 농도**다. 알파 1.0 상수로 덮으면 화면 전체가 fogColor1로 워시아웃됨 (게임뷰 분홍 화이트아웃 사고). 포그 색을 상수화할 때는 반드시 근거리 알파를 0에 가깝게, 원거리만 진하게. 또한 fogStart1은 항상 카메라-바닥 거리(~20m)보다 바깥에 둘 것.
| sunDirection | 165° (아레나 통로 방향 — 벽 차폐 회피) |

### COZY 운용 룰 (Sky Authority)

- COZY가 RenderSettings(sun/ambient Trilight/skybox)를 매 틱 인수한다. **씬에서 RenderSettings·수동 Directional Light 직접 수정 금지.**
- 씬당 Weather Sphere 1개. 시간대가 다른 씬 = Atmosphere 프로파일만 교체.
- 패키지: `Packages/com.distantlands.cozy.core` (임베디드, naju-poko에서 복사).

### ⚠ 벤더 정책: COZY는 확정이 아니라 "현재 선택"

보유 에셋이라는 이유로 확정하지 않는다 (2026-06-10 민영 방침: 항상 최선·차선 비교, 신규 구매 포함).
이 문서의 2층이 벤더 격리층이다 — 씬은 "무드 프로파일"만 알고, 그걸 COZY가 구동하는지 커스텀 시스템이 구동하는지는 교체 가능.

- **COZY 유지 조건**: 런 중 동적 날씨/시간 변화가 출시 기능에 들어갈 때 (좀비 + 날씨 압박 메커닉 등)
- **교체 검토 조건**: 맵당 고정 무드로 확정될 때 — 이 경우 COZY(550MB, 풀 데이사이클 시스템)는 과체급. 커스텀 MoodProfile(ScriptableObject → RenderSettings/포그/Volume 주입) + 전용 높이안개 에셋(예: Boxophobic Atmospheric Height Fog, OccaSoftware Buto)이 더 가볍고 출시 유지보수 부담이 작다
- 결정 시점: 날씨 메커닉 채택 여부가 정해지는 기획 마일스톤

## 새 씬 체크리스트

1. Weather Sphere 프리팹 배치 → 환경에 맞는 Atmosphere 프로파일 할당
2. Global Volume → 마스터 포스트 프로파일 참조 (복제 금지, 차이는 로컬 Volume으로)
3. 라이트는 위 레시피 표에서만. 새 레시피 필요 시 룩데브 랩에서 검증 후 표에 추가
4. RenderSettings 직접 수정 금지 (COZY 소관)
5. 룩데브 기준 오브젝트(캐릭터·좀비 더미·머티리얼 샘플)와 같은 화면에서 비교 검증

## 도구

`Assets/_Project/Scripts/Editor/CozyDuskSetup.cs` — Tools/COZY 메뉴:
- **Setup Dusk In Current Scene**: Weather Sphere 설치 + 수동 Sun/내장 포그 제거
- **Set Time From EditorPrefs**: `CozyDusk_Time`(0~1) 값으로 시간 설정 + 강제 틱
- **Create Dusk Profile**: 프로파일 복제 + sunDirection/ambientMul/fogMul 주입
- **Freeze Golden Hour**: 색 속성 일괄 상수 동결 (이 문서 2층 값)

모든 메뉴는 백그라운드 에디터에서도 동작하도록 `Raise*()` + `UpdateShaderVariables()` + `DynamicGI.UpdateEnvironment()` 강제 틱 포함.
