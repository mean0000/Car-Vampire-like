## 1. 근접공격 → 원거리 공격 전환

### 문제 인식
> "차로 좀비를 박아서 죽이는데, 왜 잘못 박으면 대미지?"

이 게임의 핵심 루프는 "차로 좀비를 치는 것"이다. 충돌 시 차에 데미지가 들어오는 것은 이 루프와 모순된다. 플레이어는 적극적으로 좀비를 향해 달려야 하는데, 잘못 박으면 벌을 받는 구조는 회피 플레이를 유도한다.

### 해결: 모든 좀비를 원거리 공격으로 전환
- **세계관 근거**: AI 나노봇이 인체를 조종하는 설정 → 투사체 발사 능력 자연스러움
- **게임플레이 효과**: 차로 박는 것 자체는 항상 유리, 좀비 공격은 회피해야 할 별개의 위협

### 삭제된 코드
- `hullDamage`, `meleeDamage`, `meleeInterval`, `_meleeTimer` — 근접 데미지 일체
- OnTriggerEnter 충돌 시 hull 데미지 로직

### 추가된 공격 시스템
**2페이즈 공격 흐름:**

```
[Search 0.6초] → [Lock 0.4초] → [Fire] → [쿨다운 2.5초]
   매 프레임         인디케이터        포물선
   예측 계산          표시+고정         투사체 발사
```

- 첫 공격은 0.2~0.5초 딜레이만 (즉시 반응)
- 사거리 25m에서 정지 후 사격

## 2. 투사체 예측 알고리즘 — 3차 진화

이동하는 차량을 맞추기 위한 예측 시스템을 3차례 설계/폐기/재설계했다.

### 1차: Angular Velocity 기반 (폐기)

```csharp
float halfAngle = -angularY * totalLeadTime * 0.75f * Rad2Deg;
Vector3 curvedVel = Quaternion.Euler(0, halfAngle, 0) * carVel;
_aimTarget = targetPos + curvedVel * totalLeadTime;
```

**의도**: 차의 회전 속도로 커브 궤적을 예측
**결과**: 탄착점이 차량 경로에서 수십 미터 빗나감
**원인**: totalLeadTime(1.8초)이 과도 + angular velocity 회전이 예측이 아닌 노이즈

### 2차: Quadratic Intercept 이차방정식 (폐기)

```csharp
// 업계 표준 공식 (Halo, L4D, Overwatch 등)
float a = carVel.sqrMagnitude - projectileSpeed * projectileSpeed;
float b = 2f * Vector3.Dot(offset, carVel);
float c = dist * dist;
// 이차방정식으로 t 계산...
```

**의도**: 게임 업계 표준인 quadratic intercept 공식 적용
**결과**: 여전히 부정확한 예측
**원인**: 이 공식은 "일정 속도" 투사체용. 우리 투사체는 Lerp 기반 고정 비행시간이라 거리마다 속도가 달라짐. 공식의 전제 자체가 맞지 않음.

**참고 자료:**
- Predictive Aim Mathematics for AI Targeting (Game Developer)
- Shooting a Moving Target (Game Developer)
- Unity Discussions: Leading a Target

### 3차: 고정 비행시간 선형 예측 (채택)

```csharp
float totalLead = remainSearch + lockTime + flightDuration;
_aimTarget = _target.position + carVel * totalLead;
```

**의도**: 투사체가 항상 flightDuration초 후 도착하므로, 그 시간만큼 현재 속도로 선형 예측
**결과**: 물리적으로 정확한 예측
**핵심 교훈**: 투사체 모델에 따라 올바른 예측 공식이 다르다. 고정 비행시간 Lerp 투사체에는 이차방정식이 아니라 단순 선형 예측이 정답.

## 3. ZombieProjectile.cs — 포물선 투사체

기존 직선 투사체를 포물선 arc로 전면 재작성.

### 포물선 궤적
```csharp
Vector3 pos = Vector3.Lerp(_start, _target, t);
pos.y += arcHeight * 4f * t * (1f - t);  // 0→peak→0 곡선
```

### 착탄 시스템
- `OverlapSphere(_target, _blastRadius)` 범위 데미지
- `CarZoneHelper.Resolve` → 존별 데미지 배율 (Front 0.5x, Rear 1.5x)
- `_landed` 가드로 이중 데미지 방지

### 인디케이터 소유권 이전
```
ZombieController (생성) → SetIndicator() → ZombieProjectile (착탄 시 파괴)
```

### 프리팹
| 프리팹 | 구성 |
|--------|------|
| ZombieProjectile | Sphere 0.25, TrailRenderer, 물리 없음 |
| BlastIndicator | Cylinder, 투명 빨강, scale = blastRadius × 2 |

## 4. 좀비 변종 시스템

### 아키텍처 결정: enum 분기
3종 좀비가 80% 코드를 공유(이동, 스폰, 킬 판정, 터레인 추종, Feel 피드백). 상속 구조는 공유 상태를 분리하는 복잡성만 증가시킴.

```csharp
public enum ZombieType { Ranged, Charger, Laser }
```

FixedUpdate에서 type switch로 공격 로직만 분기:
```csharp
switch (zombieType)
{
    case ZombieType.Ranged:  UpdateRangedAttack(carDist); break;
    case ZombieType.Charger: UpdateCharger(carDist);      break;
    case ZombieType.Laser:   UpdateLaser(carDist);        break;
}
```

### 4-A. Ranged (원거리형) — 기존 좀비
- 25m 사거리, 포물선 투사체
- 선형 예측 + 랜덤 산포

### 4-B. Charger (돌진형) — 녹색

**역할**: 코너 차단자. 직선에서는 위협이 안 되지만, 코너링 시 안쪽을 차단.

**설계 근거**: "뒤에서 오는 돌진형을 막을 방법이 없다" → 코너링 시에만 위협적이어야 한다. 그래야 특정 방향 코너링을 차단하는 전술적 역할을 수행.

**상태 머신:**
```
Stalk ──(거리+코너링 감지)──→ Position ──(1.2초)──→ Charge ──(충돌/타임아웃)──→ Recover ──(2초)──→ Stalk
```

| 상태 | 행동 | 속도 |
|------|------|------|
| Stalk | 12m 내 대기, angular velocity로 차 코너링 감지 | 기본 |
| Position | 커브 안쪽으로 이동 (carFwd × 8 + carRight × turnSign × 6) | 기본 |
| Charge | 차량 예측 위치로 돌진, carAvoidance 비활성 | ×1.8 |
| Recover | 쿨다운 | 기본 |

**포지셔닝 수학:**
```csharp
// Unity: angularVelocity.y > 0 = 좌회전, 안쪽 = +carRight
Vector3 innerPos = carPos + carFwd * 8f + carRight * turnSign * 6f;
```

**충돌 판정:**
| 조건 | 결과 |
|------|------|
| 정면 + 차속 ≥ 3 | 일반 킬 (보상 있음) |
| 측면/후면 | 차에 8 데미지 → 좀비 자폭 (보상 없음) |

**플레이어 대응:**
- 반대 방향으로 꺾기
- 정면으로 맞서서 킬
- 드리프트/부스트로 돌파

### 4-C. Laser (레이저형) — 흰색

**역할**: 원거리 히트스캔. 조준선으로 위협을 알려주고 즉발 피해.

**상태 머신:**
```
Idle ──(30m 진입)──→ Aiming ──(2초)──→ Firing ──(0.3초)──→ Cooldown ──(3.5초)──→ Idle
```

| 상태 | 시각 효과 | 데미지 |
|------|----------|--------|
| Aiming | 붉은 조준선 (0.05 폭, 반투명) | 없음 |
| Firing | 밝은 주황 빔 (0.3→0.05 페이드) | 6 (CarZone 배율) |
| Cooldown | 없음 | 없음 |

**히트스캔 구현:**
```csharp
int mask = 1 << _target.gameObject.layer;  // 차량 레이어만
Physics.Raycast(origin, dir, out hit, laserRange, mask);
```

**특이사항:**
- 한번 조준 시작하면 거리 무관하게 발사 가능 (이탈 취소 없음)
- LineRenderer는 런타임 AddComponent (프리팹 의존성 없음)
- OnDestroy에서 material Destroy (GPU 메모리 누수 방지)

## 5. ZombieSpawner — 난이도별 타입 배분

### 프리팹 관리
```csharp
[SerializeField] GameObject chargerPrefab;  // 녹색
[SerializeField] GameObject laserPrefab;    // 흰색
```
null이면 기본 `zombiePrefab`으로 폴백.

### 난이도별 출현 확률

| difficulty | Ranged | Charger | Laser |
|-----------|--------|---------|-------|
| 0 ~ 0.2 | 100% | — | — |
| 0.2 ~ 0.5 | 70% | 30% | — |
| 0.5 ~ 1.0 | 50% | 30% | 20% |

```
difficulty = Max(time/600s, distance/5000m)
```

초반에는 Ranged만으로 게임 학습, 중반부터 Charger로 코너링 긴장감, 후반에 Laser 추가로 회피 부담 증가.

## 6. 품질 보증 — Stab + Codex 리뷰

총 6회 병렬 리뷰 실시. 15건 이상 이슈 발견 및 수정.

### 투사체 예측 관련

| 이슈 | 심각도 | 수정 |
|------|--------|------|
| distFactor가 근거리 리드를 0으로 만듦 | High | distFactor 제거 |
| `_target` null 가드 없음 | High | null 체크 추가 |
| 이차방정식이 고정시간 투사체와 불일치 | Critical | 선형 예측으로 교체 |

### 좀비 변종 관련

| 이슈 | 심각도 | 수정 |
|------|--------|------|
| `_charging` Init 미초기화 | Critical | 상태 전체 리셋 |
| Material 누수 (EnsureLaserLine) | High | OnDestroy에서 Destroy |
| Shader.Find null 미체크 | Medium | null 체크 추가 |
| Raycast 레이어마스크 없음 | High | 차량 레이어만 대상 |
| LaunchKill 레이저 미정리 | Medium | enabled = false |
| Position 조기 종료 | High | `!carTurning` 제거 |
| OnTriggerEnter `_charging` 레이스 | High | `_chargerState` 직접 체크 |
| innerPos 부호 오류 | Critical | `-` → `+` (Unity 좌표계) |
